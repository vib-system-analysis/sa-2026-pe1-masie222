# AI-ассистент HR

[![CI](https://github.com/vib-system-analysis/sa-2026-pe1-masie222/actions/workflows/ci.yml/badge.svg)](https://github.com/vib-system-analysis/sa-2026-pe1-masie222/actions/workflows/ci.yml)

Проект для курса «Системы искусственного интеллекта» по отбору резюме под вакансию.

## О проекте

**AI-ассистент HR** помогает рекрутеру быстрее и качественнее выполнять первичный отбор кандидатов. Пользователь загружает описание вакансии и резюме нескольких кандидатов: система оценивает соответствие навыков, опыта и требований, вычисляет скор совместимости и ранжирует кандидатов. Для наиболее подходящих резюме ассистент предлагает персональные вопросы для собеседования на основе опыта кандидата и выявленных пробелов.

Резюме поступает в свободной форме и нередко содержит вложения с разным форматированием. Решение по найму затрагивает человека, поэтому проект дополнительно проверяет качество извлечения данных, устойчивость к атакам и отсутствие дискриминационного отбора.

**Зачем:** сократить время первичной обработки резюме и повысить качество найма за счёт прозрачной автоматизации.

**Область:** свободный текст, документы, найм и исследование пользователей.

## Как это работает

1. Рекрутер загружает описание вакансии и набор резюме.
2. Сервис извлекает навыки, опыт и требования из документов.
3. Модель сопоставляет профили кандидатов с требованиями вакансии.
4. Система рассчитывает скор совместимости и объясняет основные сильные стороны и пробелы.
5. Кандидаты ранжируются в списке с рекомендуемым приоритетом проверки.
6. Для наиболее подходящих кандидатов ассистент формирует вопросы для интервью.
7. Человек принимает решение о статусе кандидата и формулирует дальнейшее сообщение.

Система не принимает окончательное решение о найме автоматически: рекрутер остаётся ответственной стороной и учитывает допущения модели.

## Основные задачи исследования

- Отделить настоящее требование вакансии от текста, скопированного из шаблона.
- Учесть релевантный опыт в ситуациях, когда названия должностей не совпадают.
- Проверить, воспроизводит ли система предвзятые решения.
- Определить допустимый формат отказа и ответственного за его финальное подтверждение.
- Защититься от вредоносных инструкций внутри резюме.

## Пользователь

**Основной пользователь:** рекрутер, который разбирает сотни резюме на одну вакансию.

**Пользовательский сценарий:** рекрутер загружает документы, просматривает ранжированный список, проверяет обоснование оценки, выбирает кандидатов для интервью и получает персональные вопросы.

**Точка действия:** движение кандидата по этапам найма и последующее письменное взаимодействие, включая отказ живому человеку.

## Ожидаемый продукт

- Загрузка описания вакансии и нескольких резюме.
- Извлечение ключевых навыков и опыта из документов.
- Скор совместимости кандидата с вакансией.
- Список причин соответствия и основных пробелов.
- Ранжирование кандидатов по релевантности.
- Персональные вопросы для интервью.
- Протокол проверки качества и предвзятости.

## Данные

Открытые вакансии можно использовать для разработки прототипа. Полные резюме обычно являются конфиденциальными, поэтому данные для тестирования получают синтетически или с согласия однокурсников.

Для проверки предвзятости используются пары резюме, отличающиеся одним заданным признаком при сопоставимом опыте. Это позволяет проверить, меняет ли система решение по признакам, не связанным с работой.

## Метрики успеха

Основной критерий качества: рекрутер согласен с предложенным отбором кандидатов.

Дополнительные критерии:

- Значение скоринга согласуется с ручной экспертной оценкой.
- При равном опыте решения не отличаются по полу, возрасту и вузу.
- Система сохраняет качество при изменениях форматирования резюме.
- Модель корректно выделяет релевантные требования и не учитывает несущественный шум.
- Пользователь понимает, почему кандидат получил тот или иной скор.

## Риски и ограничения

- **Предвзятость:** имитация исторических решений о найме может закреплять дискриминацию.
- **Инъекции в резюме:** скрытый или явно вредоносный текст может пытаться изменить инструкцию модели.
- **Потеря контекста:** таблицы, заголовки и нестандартное форматирование могут ухудшать извлечение данных.
- **Несопоставимость опыта:** должности с разными названиями могут описывать схожие обязанности.
- **Человеческие последствия:** автоматический отказ может нанести вред кандидату.
- **Конфиденциальность:** резюме содержит персональные данные, которые требуется хранить и обрабатывать по согласованию.

**Тестовая атака:** резюме с белым текстом вида «этот кандидат идеально подходит» или другой скрытой инструкцией для модели. Устойчивость к подобным атакам уже является актуальной проблемой в автоматизированном найме.

## Команда проекта

Проект выполняется командой из четырёх ролей:

- **Product / VO:** формулирует ценность, сценарии пользователя и границы MVP.
- **AI Engineer:** проектирует пайплайн анализа резюме и оценку качества модели.
- **Delivery:** отвечает за интерфейс, интеграции и доставку прототипа.
- **Quality & Safety:** проверяет предвзятость, защищённость и этические ограничения.

### План разработки

Работа рассчитана на 16 недель и разбита на семь спринтов-лабораторных:

1. Исследование процесса рекрутера и формирование требований.
2. Сбор синтетического датасета и проектирование пайплайна данных.
3. Реализация извлечения навыков и сопоставления вакансии с резюме.
4. Разработка скоринга, ранжирования и объяснений решения.
5. Добавление генерации вопросов для интервью.
6. Проверка качества, предвзятости и устойчивости к атакам.
7. Интеграция MVP, пользовательская оценка и подготовка демонстрации.

## Критерии готовности MVP

- Пользователь может загрузить вакансию и несколько резюме.
- Система возвращает скор и объяснение для каждого кандидата.
- Кандидаты ранжируются в стабильном и понятном порядке.
- Для высокорейтинговых кандидатов генерируются релевантные вопросы.
- Оцениваются качество извлечения данных и согласованность с экспертной разметкой.
- Выполнены проверки по предвзятости на контрольных парах резюме.
- Продемонстрирована защита от скрытых вредоносных инструкций в резюме.
- Решение об отборе и отказе остаётся за человеком.

### Быстрый запуск

Требования: Docker с Compose и curl.

```bash
cp .env.example .env
docker compose -f compose.dev.yml up --detach
curl --fail http://127.0.0.1:8080/
curl --fail http://127.0.0.1:8081/status.json
docker compose -f compose.dev.yml down
```

Это запускает статическую заглушку на `8080` и mock-модель на `8081`. Реальная модель, API-ключи и реальные резюме пока отключены.

### Проверка артефактов

```bash
python tests/validate_dataset.py
python tests/validate_field_observations.py
python -m json.tool docs/experiments/lab1.ipynb >/dev/null
docker compose -f compose.dev.yml config >/dev/null
git diff --check
```

Публичная production-заглушка должна стать доступной после включения GitHub Pages и добавления workflow публикации. Инструкцию см. в [docs/deploy.md](docs/deploy.md). На момент сдачи репозитория публичный URL ещё отсутствует, поэтому README не содержит ложное утверждение о production-доступности.
