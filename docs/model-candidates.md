# Кандидаты моделей и токен-бюджет

## Кандидаты

| Кандидат | Размещение | Качество для MVP | Риски | Примерная цена расчёта |
|---|---|---|---|---|
| Публичный API SOTA-модели | облако | Сильное извлечение и ответ по JSON | Зависимость от API, персональные данные резюме | Рассчитывается по фактическому тарифу провайдера перед запуском |
| Российская облачная LLM | облако РФ | Возможна локализация и приемлемое извлечение | Точный output-contract требует проверки | Требует закрытого коммерческого расчёта у провайдера |
| Локальная open-weight модель 7–14B | собственный сервер | Контроль данных и офлайн-возможность | Меньшая точность, GPU и обслуживание | GPU: от 80 ₽ в час при виртуальной машине с 24 GB VRAM; тариф проверить перед запуском |

До начала обработки реальных резюме владелец AI подтверждает поставщика и правила передачи персональных данных. Точные прайс-листы не считаются предварительно проверенными источниками и не включены в расчёт.

## Базовый сценарий

Для типового резюме в MVP предполагаем:

- текст резюме и вакансии: 8 000 входных токенов;
- системные данные, schema и исходные выдержки: 2 000 входных токенов;
- извлечение фактов: до 1 500 выходных токенов;
- скоринг с объяснением: до 2 000 выходных токенов;
- вопросы интервью: до 1 000 выходных токенов.

Итого на полный сценарий: около **13 500 входных и 4 500 выходных токенов**.

При лимите 20 ₽ за резюме и среднем модельном тарифе сценарий не должен превышать этот бюджет. Перед каждой реализацией считаем фактическую стоимость по формуле:

```text
стоимость = входные_токены × цена_входного_токена
          + выходные_токены × цена_выходного_токена
          + стоимость_инфраструктуры_на_сценарий
```

## Выбранный старт

1. Для первой лабораторной используется публичный API только с синтетическими данными.
2. Реальные резюме не отправляются до подписания правил обработки данных.
3. Все вызовы логируют версию модели, число токенов, стоимость и латентность без персонального текста.
4. В результате сравнения двух синтетических сценариев выбирается наименьшая стоимость при проходе quality-порогов.

## Локальная модель

Если облако недоступно или стоимость превышает 20 ₽ на резюме:

- хранение данных остаётся в контролируемой среде;
- требуются GPU-сервер с не менее чем 24 GB VRAM и мониторинг очереди;
- качество извлечения и long-context оцениваются заново;
- время ответа может превышать 30 секунд;
- добавляется кэширование по содержимому резюме;
- производительность сравнивается на одном наборе ответов с облачным кандидатом.

## Деградация и лимиты

- При исчерпанном дневном бюджете сервис возвращает очередь на ручную обработку без прогноза скоринга.
- При обязательном общем лимите система ставит задачу на приостановку вместо молчаливого увеличения стоимости.
- При недоступности модели используется только структурированная форма критериев вакансии, а не устаревшая модельная оценка.
- При превышении латентности в 30 секунд в 10 последовательных сценариях система переключается в ручной режим и отправляет алерт.
- При утечке ключа API вызовы блокируются до ротации секретов.

## Критерии выбора

- Проходит schema validation на ≥95% синтетических сценариев.
- Затраты в пределах 20 ₽ на один полный сценарий.
- Совпадение с ручной разметкой ≥80%.
- В 200 контрольных резюме нет расхождения по нерелевантным признакам.
- Поддерживает воспроизводимый JSON contract и версионирование промптов.
